# Personal website

A single-page academic site. Publications update automatically from ORCID.

## Edit your content

Everything you write lives in `data/content.yml`. Edit it, save, and refresh the
page. Replace these two files with your own:

- `assets/headshot.jpg` — your photo, square, **440×440 px** (twice its
  220 px display size, for sharp screens). A full-resolution camera photo
  is roughly 25× heavier and slows every page load, so resize it first.
  `assets/apple-touch-icon.png` is the same photo at 180×180 px.
- `assets/<last>-<first>_CV*.pdf` — your CV. The site builds the expected
  prefix from your name in `content.yml`, so with `first_name: "Sarang"` and
  `last_name: "Bhagwat"` it looks for files starting with `Bhagwat-Sarang_CV`
  (e.g. add a date suffix like `Bhagwat-Sarang_CV_2026-07.pdf`); if several
  match, the highest-sorting name wins. The link is wired up from
  `data/cv.json`, which `scripts/detect_cv.py` regenerates in CI whenever
  `assets/` or `content.yml` changes — do not edit it by hand.

The static parts of `index.html` are generated too, so the page reads
correctly before JavaScript runs and in link previews (LinkedIn, Slack),
which never run it. `scripts/sync_head.py` builds them from `content.yml`
and `data/cv.json`: the title and meta description, the nav name, the hero
(photo, name, title, tagline, CV button, links), the Scholar link, the
footer, and the `generated:head` block (canonical URL from `CNAME`, favicon,
Open Graph and Twitter card tags, schema.org Person data). It also writes
`assets/favicon.svg` from your initials. Do not edit anything between the
`<!-- generated:... -->` markers by hand. CI runs it whenever `content.yml`
or `assets/` changes; run `python scripts/sync_head.py` yourself if you want
them updated before you push.

Your name goes in the `meta:` block of `data/content.yml` as `first_name`,
`middle_name` (optional), and `last_name`. Everything that shows your name —
the page, the title, the CV filename — is built from those parts. Also set your
`orcid_id` and `scholar_url` there. Do **not** edit `data/publications.json` —
it is generated from ORCID.

The ORCID sync (`scripts/sync_orcid.py`, daily in CI) is **add-only**: it can add
publications and authors, and update titles, venues, years and DOIs, but it
never removes a publication or an author already in `publications.json`. A
flaky ORCID response (a failed author lookup, an empty works list, a work
hidden on ORCID) therefore can't erase anything from the site. If the existing
file can't be read, the sync refuses to write and exits with an error. To remove
a publication or author on purpose, take it off ORCID first, then delete it from
`publications.json` by hand; this is the one exception to "do not edit".

## Sections driven by `content.yml`

Beyond the basics, these optional keys add sections; each one hides itself when
empty, so you can leave any of them out:

- `software:` — your tools. Each entry has `name`, `role`, `description`
  (markdown links allowed), a `repo` (`"owner/name"`), an optional `pypi`
  package name, and an optional `url`. Star counts and monthly downloads are
  fetched automatically into `data/software.json` — **do not edit that file**;
  it is regenerated by `scripts/sync_software.py` (weekly in CI, or run it
  yourself). Run it locally with `python scripts/sync_software.py`. A card
  shows stars only at 25 or more and downloads only at 200/month or more
  (`MIN_STARS_SHOWN` / `MIN_MONTHLY_DOWNLOADS_SHOWN` in `js/main.js`).
- `proposals:` — `{year, description}` entries for the "Selected proposal
  development" section (sponsor, amount, PI, outcome, and your role worded as on
  the CV).
- `research_vision:` — optional 2–3 `{heading, body}` thrusts shown above your
  research interests. Keep these vision-level; save the details for your
  statement.
- `research_note:` — one short line shown below your research interests (e.g.
  pointing readers to your full statement). Omit to hide it.
- `first_author_dois:`, `cofirst_dois:`, `corresponding_dois:` — authorship-role
  tags, by DOI (lowercase, matching a `doi` in the ORCID-generated
  `publications.json`). ORCID can't tell these apart, so tag them here. The
  "Selected publications" lead-in above the full list is built automatically
  from every DOI in these lists (newest first), and each role adds its own badge
  ("First author", "Co-first author", "Corresponding author"). A paper may appear
  in more than one list. Works that ORCID types as `preprint` also get an
  outlined "Preprint" badge automatically; nothing to tag by hand.
- `selected_order:` — optional DOIs pinned to the top of "Selected
  publications" in the order listed; the rest follow newest first.
- `talks:` — `{year, title, venue, url}` entries for the "Invited talks"
  section (`url` is optional).
- `news:` — `{date, text}` one-liners shown below the hero.
- `awards:` — `{year, description}` entries (fellowships and honors).
- `teaching_outreach:` — `{year, description}` entries for the "Selected
  teaching & outreach" section (courses, mentoring, outreach events).
- `service:` — `{year, description}` entries for the "Selected professional
  service" section (editorial boards, session chairs, peer review).
